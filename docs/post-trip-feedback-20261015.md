# Post-trip feedback

New form: 8dc19365-8dd7-49e7-92fb-fdd697572771. Separate from the pre-departure survey. All-English custom UI; same canonical public-form URL and existing form_submissions save/notification route. Issue-only links resolve the trusted form and preserve the opaque issue.

Problem: gather feedback and many original photos/videos after a completed trip, without an arbitrary attachment-count cap. Supports overseas customer evidence and operational efficiency; no Nika WBS or package-tour changes.

Acceptance: rating, Good, helpful service, More, optional photos and videos; repeated file addition/removal; no maxFiles setting; sequential uploads split automatically into 8 MiB parts; retries retain successful parts/files in the open page; private media collection pages keep the answer payload bounded regardless of file count. Large originals download as a stream and support HTTP byte ranges. Keep the page open: browser file handles and retry state live in RAM and do not survive a reload.

Consent: required handling checkbox v2; five independent optional unchecked choices for anonymous quotes, photos, videos, story contact and first-name use. Uploading is not publication permission. Story publication needs separate final content approval. Face/voice and third-party music rights disclosed. No sensitive customer information publication through this consent. Existing answer rows and old consent values remain unchanged.

Advocate: collecting more original material supports marketing and service improvement. Critic: giant batches can exceed storage/request limits or lose progress; permissions can become ambiguous. Mitigation: bounded parts and collection pages, signed upload sessions, server-side part length/type/hash verification, idempotent retries, completion verification, fail-closed publication choices and no automatic publication.

Ownership: existing line-flattravel Worker + UPLOADS KV; no new binding/provider/secret/scheduler. Session and chunk endpoints are restricted to this exact form and memory_photos field. Upload, part, manifest and album data retain existing 180-day expiry and private access. Signed URLs only; public bypass must return404. No FlatWorker/customer-send/business-state change. saveToMetadata=false; tags/scenarios=null.

Quality evidence before release: server typecheck and real Hono route tests pass with a 27 MiB video split/reassembled byte-exactly, range reads crossing part boundaries, forged-token/signature refusal, absent/truncated/changed part refusal, idempotent retry, MIME spoof refusal, bounded completion proofs and 131-item album chain. Client tests pass with interrupted/retried parts, cached media on answer retries and 1,025 files across bounded collection pages. Source self-review approves this scoped design, subject to guarded release and public/API readback. Required existing regression checks remain in both deployment guards. No successful synthetic form submit or staff/customer message is used for verification. Browser visual QA omitted under user preference.
