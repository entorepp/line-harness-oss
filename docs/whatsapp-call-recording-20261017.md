# WhatsApp recording and Slack summaries

Prepared on2026-10-17 at the owner request. Recording is OFF by default. Do not mark this feature live from build/mock results.

The call-owning browser mixes its existing microphone and remote audio. In announced mode a fixed English recording/AI-summary/team-sharing notice is sent down the live audio sender before capture. In staff-confirmed mode capture requires a per-call notice/consent confirmation. Recording can stop without hanging up. Complete independent8-minute segments are encrypted at rest in private KV with the configured30/90-day TTL; no public file URL is created. Browser closure can lose the current segment; the UI warns while capture or upload is pending. Reload does not resume recording or redial.

Existing Worker/D1 owns per-call recording and per-part hashes. The minute job handles completed uploads only, reuses acknowledged transcripts and summary, and bounds provider work per tick. It transcribes with gpt-transcribe and summarizes with gpt-4.1-mini using store=false/no tools, then posts Japanese summary plus Slack audio files in one thread. Default routing requires the exact existing friend Slack channel; unmatched contacts fail closed. A dedicated channel can be configured after selection. Provider ambiguity enters attention and never auto-reposts. There is no commercial-state, supplier, case, payment or Nika write.
